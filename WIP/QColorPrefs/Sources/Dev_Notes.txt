CONFIGURING REGISTRY VALUES
---------------------------
To configure which registry values QColorPrefs will save and restore, you must
edit the source code file QColorPrefs.cpp.

All registry values are read from/stored in:
  HKEY_CURRENT_USER\Software\Marcus Aurelius Software LLC\QSPICE\[Preferences]

Locate the g_registryValues vector (around line 72) and add the values you
want to backup, organized by section:

  std::vector<RegistryValue> g_registryValues = {
      // Schematic-related values
      {SCHSEC, "CADHighlightColor", "Highlight Color"},
      {SCHSEC, "CADBackgroundColor", "Background"},
      {SCHSEC, "CADwireColor", "Wire Color"},
      ...
      
      // Waveform-related values
      {WAVSEC, "DataColor1", "Waveform Trace #1 Color"},
      {WAVSEC, "DataColor2", "Waveform Trace #2 Color"},
      {WAVSEC, "BackgroundColor", "Background Color"},
      ...
  };

Each entry consists of three parameters:
  - Section name (e.g., SCHSEC for "schematic", WAVSEC for "waveform") - 
    used to organize the preferences file and enable selective operations
  - Value name - the name of the REG_SZ (string) value in the registry
  - Comment - descriptive text that appears as an inline comment in the
    generated .qcolorpref file (use "" for no comment)

The section names are purely for organization in the preferences file and
help keep related settings grouped together. All values are still read from
and written to the same registry location.

After adding your values, recompile the program.

COMPILATION
-----------
To compile QColorPrefs, you need a C++11 compatible compiler.

Using Microsoft Visual C++ compiler:
  cl QColorPrefs.cpp /EHsc /std:c++11

Or using MinGW:
  g++ -std=c++11 QColorPrefs.cpp -o QColorPrefs.exe

The program uses only standard C++ libraries and Windows API, so no external
dependencies are required.

ARCHITECTURE NOTES
------------------
The program uses a vector-based configuration system where each registry
value is defined by a RegistryValue struct containing:
  - section: Section identifier (SCHSEC or WAVSEC constants)
  - valueName: Registry value name
  - comment: Human-readable description for the .qcolorpref file

Key functions:
  SavePreferences()     - Saves registry values to .qcolorpref file
  UpdatePreferences()   - Updates existing .qcolorpref file with current values
  RestorePreferences()  - Restores registry values from .qcolorpref file
  GetCurrentDateTime()  - Returns formatted date/time string
  GetVersionString()    - Extracts version without compile timestamp
  PrintVerboseLine()    - Formats aligned before/after output

The SavePreferences(), UpdatePreferences(), and RestorePreferences() functions 
support optional section filtering, allowing selective save/restore/update 
operations for schematic or waveform values independently.

The preferences file format uses INI-style sections with inline comments,
making it human-readable and easy to edit or share.

Verbose and test modes use per-section alignment for professional output:
  - Each section computes its own label, before-value, and after-value widths
  - Values are aligned within their section (not globally)
  - This prevents misalignment between hex colors and numeric values
  - Blank lines separate sections visually


GLOBAL FLAGS
------------
The program uses two global boolean flags that can be set via command line:

  g_verbose (set by -v flag):
    - Shows detailed before/after values during operations
    - Displays per-value changes with alignment
    - Shows additional warnings and diagnostic information

  g_testMode (set by -t flag):
    - Preview mode - shows what would happen without making changes
    - Skips file writing and registry modification
    - Skips user confirmation prompts
    - Automatically shows verbose-style output
    - Reports only changed values (not total count)


FILE FORMAT
-----------
The .qcolorpref file format:

  # This file was {created|modified} by QColorPrefs {version} on {datetime}
  # Generated automatically - do not edit unless you know what you're doing
  # Registry path: HKEY_CURRENT_USER\{registry_path}
  {optional: # Section filter: [section] only}

  [section1]
  key1=value1       # Comment 1
  key2=value2       # Comment 2

  [section2]
  key3=value3       # Comment 3

Features:
  - Header with metadata (version, date/time, registry path)
  - INI-style section markers
  - Inline comments for each key (aligned within section)
  - Comments and blank lines are ignored during restore
  - Users can comment out lines with # to prevent restoration


DEVELOPER TROUBLESHOOTING
-------------------------
"Error: No registry values configured to save"
  - You need to add values to the g_registryValues vector in the source
    code and recompile. See CONFIGURING REGISTRY VALUES section above.

Build errors related to missing includes:
  - Ensure you have the Windows SDK installed
  - QColorPrefs requires: <windows.h>, <string>, <vector>, <iostream>,
    <fstream>, <map>, <algorithm>, <ctime>

Linker errors:
  - Make sure advapi32.lib is linked (automatic with most Windows compilers)
  - For MinGW, this should be automatic

Deprecated function warnings (localtime):
  - Fixed in v1.3 - now uses localtime_s() for Windows
  - If you see this warning, update to latest code

Alignment issues in verbose output:
  - Ensure labelWidth, beforeValueWidth, and afterValueWidth are computed
    per-section, not globally
  - Check that PrintVerboseLine receives correct width parameters


EXTENDING THE PROGRAM
---------------------
To add support for additional QSpice preferences:
  1. Identify the registry value name in QSPICE\Preferences key
  2. Determine if it's a REG_SZ (string) type (required)
  3. Add entry to g_registryValues vector with appropriate section
  4. Add descriptive comment for the preferences file
  5. Recompile

To add support for additional value types (DWORD, BINARY, etc.):
  - Modify the RegistryValue struct to include type information
  - Update SavePreferences() to handle different value types
  - Update RestorePreferences() to write different value types
  - Update file format to distinguish between types
  - Add functions ReadRegistryDWord(), WriteRegistryDWord(), etc.

To add new command-line options:
  1. Add new boolean flag variable (e.g., bool g_newFeature = false)
  2. Update command-line parsing in main() to recognize the flag
  3. Update ShowUsage() to document the new option
  4. Implement the feature in appropriate functions
  5. Test thoroughly with various combinations of flags

    □ Save schematic only (-ssch)
    □ Save waveform only (-swav)
    □ Update all (-uall)
    □ Update schematic only (-usch)
    □ Update waveform only (-uwav)
    □ Restore all (-rall)
    □ Restore schematic only (-rsch)
    □ Restore waveform only (-rwav)

  Test mode:
    □ Test mode with save (-t -sall)
    □ Test mode with update (-t -uall)
    □ Test mode with restore (-t -rall)
    □ Verify no files created/modified in test mode
    □ Verify no registry changes in test mode
    □ Verify changed count reporting is accurate

  Verbose mode:
    □ Verbose save (-v -sall)
    □ Verbose update (-v -uall)
    □ Verbose restore (-v -rall)
    □ Verify per-section alignment works correctly
    □ Verify before/after values display correctly

  Combined modes:
    □ Test + verbose (-t -v -rall)
    □ Verify flags can appear in any order

  Edge cases:
    □ File doesn't exist (update should fail)
    □ File is empty
    □ File has only comments
    □ File missing section headers
    □ File with unknown keys (should be preserved)
    □ Registry key doesn't exist
    □ Cancel on overwrite prompt
    □ Cancel on restore prompt

  File format:
    □ Header includes correct version
    □ Header includes current date/time
    □ Comments are aligned within sections
    □ All registry values have comments
    □ Blank lines between sections

  Error handling:
    □ Invalid command-line options
    □ Missing filepath
    □ Invalid file format
    □ Registry access denied
    □ Disk full when writing
